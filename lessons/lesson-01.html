강체 변환과 좌표계

SLAM이 하는 일을 한 문장으로 줄이면 로봇이 지금 어디에 있고 어느 쪽을 보는지, 즉 pose를 계속 추정하는 것입니다. pose는 회전과 이동으로 이루어지고, 둘을 합친 것이 강체 변환입니다. 뒤에 나올 PnP, 번들 조정, 포즈 그래프가 모두 이 변환을 추정하는 문제입니다.

월드(map)에서 본 점 p

슬라이더를 움직이면 그림과 행렬이 함께 바뀝니다. 처음 값은 6절의 예제와 같습니다. 축 색은 rviz와 같게 x 빨강, y 초록입니다.

1. 왜 이걸 제일 먼저 배우나

pose는 두 가지로 이루어집니다.

  • 회전(rotation): 어느 방향을 보고 있는가
  • 이동(translation): 어디에 있는가

사실 매일 쓰고 있는 개념입니다. ROS의 tf 트리 map → odom → base_link → laser의 화살표 하나하나가 강체 변환입니다. 이번 강의는 그걸 수식으로 정확히 이해하는 시간입니다.

2. 좌표계(frame)

같은 점도 어느 좌표계에서 보느냐에 따라 좌표값이 달라집니다. 로봇 바로 앞 1m에 컵이 있으면, 로봇 좌표계에서는 (1, 0, 0)이지만 월드 좌표계에서는 로봇이 서 있는 위치와 방향에 따라 (5, 3, 0)일 수도 (-2, 7, 0)일 수도 있습니다.

좌표계의미ROS에서
World (w)고정된 기준map
Body (b)로봇 몸체base_link
Camera (c)카메라camera_link, camera_optical_frame
자주 걸리는 함정: 카메라 광학 좌표계ROS 로봇 몸체는 x 앞, y 왼쪽, z 위입니다. 카메라의 optical frame은 z 앞, x 오른쪽, y 아래입니다. Visual SLAM 코드는 거의 다 optical frame 기준이라 처음에 여기서 많이 헷갈립니다. 6강에서 다시 다룹니다.

3. 회전 행렬

2D부터

평면에서 θ만큼 회전시키는 행렬입니다.

R(θ) = [ cosθ  -sinθ ]
       [ sinθ   cosθ ]

점 (1, 0)을 90° 돌리면 cos90° = 0, sin90° = 1이므로 아래처럼 (0, 1)이 됩니다. x축 위의 점이 y축으로 돌아갔으니 맞습니다.

[ 0  -1 ] [1]   [0]
[ 1   0 ] [0] = [1]

3D에서: 열이 곧 축이다

가장 중요한 해석회전 행렬의 각 열은 회전된 좌표계의 x, y, z축을 원래 좌표계에서 본 방향 벡터입니다. Rwb의 첫 번째 열은 로봇의 앞 방향이 월드에서 어디를 가리키는지입니다.

위 그림의 Twb 행렬에서 왼쪽 위 2×2의 첫 열을 보세요. yaw를 바꾸면 그 열이 로봇의 빨간 x축 방향과 똑같이 움직입니다.

성질

  1. RᵀR = I (직교 행렬). 그래서 역행렬이 그냥 전치 Rᵀ이고, 계산이 아주 쌉니다.
  2. det(R) = +1. -1이면 회전이 아니라 거울 반사입니다.
  3. 이 두 조건을 만족하는 행렬의 집합을 SO(3)(Special Orthogonal group)라고 합니다. 3강에서 다시 나옵니다.

회전은 순서가 중요하다

책 한 권을 들고 해보세요. x축으로 90° 돌린 뒤 z축으로 90° 돌린 결과와, z축 먼저 돌린 뒤 x축으로 돌린 결과가 다릅니다. 행렬로 쓰면 Rz·Rx ≠ Rx·Rz입니다. 코드에서 곱하는 순서를 틀리면 에러 없이 조용히 틀린 값만 나옵니다.

4. 점 변환 공식과 표기법

카메라 좌표계의 점 pc를 월드 좌표계로 옮기는 공식입니다.

p_w = R_wc · p_c + t_wc
표기 규칙 (Visual SLAM 14강, ORB-SLAM과 같음)Twc는 c 좌표계의 좌표를 w 좌표계의 좌표로 바꾸는 변환입니다. 아래첨자를 오른쪽에서 왼쪽으로, c → w로 읽습니다. twc는 월드에서 본 카메라의 위치이기도 합니다. 카메라 원점 (0,0,0)을 넣으면 pw = twc가 나오기 때문입니다.

이 표기를 쓰면 변환을 이어 붙일 때 안쪽 첨자가 맞물려 사라지므로, 순서를 틀릴 일이 줄어듭니다.

T_wc = T_wb · T_bc     (안쪽 첨자 b끼리 맞물림)

5. 동차 좌표

R·p + t는 곱셈 뒤에 덧셈이 붙어서, 여러 번 이어 붙이면 식이 금방 지저분해집니다.

p_w = R_wb (R_bc p_c + t_bc) + t_wb

그래서 점 뒤에 1을 붙여 차원을 하나 늘리고, 회전과 이동을 4×4 행렬 하나로 묶습니다. 이제 변환을 이어 붙이는 것이 그냥 행렬 곱셈입니다. 이런 4×4 행렬의 집합이 SE(3)(Special Euclidean group)입니다.

T = [ R   t ]      p̃ = [ p ]      T·p̃ = [ R·p + t ]
    [ 0ᵀ  1 ]          [ 1 ]             [    1    ]

역변환

T⁻¹ = [ Rᵀ   -Rᵀ·t ]
      [ 0ᵀ     1   ]

Twc를 알면 Tcw = Twc⁻¹이고, 이걸로 맵의 3D 점을 카메라 좌표로 가져옵니다. 6강에서 점을 이미지에 투영할 때 씁니다.

여기서 많이 틀립니다역변환의 이동 부분은 -t가 아니라 -Rᵀ·t입니다.

6. 손으로 풀어보는 예제

상황: 로봇이 월드 좌표 (2, 1)에 서서 yaw 90°로 +y 방향을 봅니다. 카메라는 로봇 앞 0.5m에 같은 방향으로 달려 있습니다(optical frame은 일단 무시하고 x가 앞이라고 하겠습니다). 카메라가 정면 1m에 장애물을 봤습니다. pc = (1, 0, 0). 장애물의 월드 좌표는?

1단계, 카메라 → 로봇: Rbc = I, tbc = (0.5, 0, 0)이므로 pb = (1, 0, 0) + (0.5, 0, 0) = (1.5, 0, 0)

2단계, 로봇 → 월드: Rwb = R(90°), twb = (2, 1, 0)

R(90°)·(1.5, 0) = (0·1.5 − 1·0,  1·1.5 + 0·0) = (0, 1.5)
p_w = (0, 1.5) + (2, 1) = (2, 2.5)

검산: 로봇이 (2, 1)에서 +y를 보고 있고 장애물이 정면 1.5m에 있으니 (2, 2.5)가 맞습니다. 위 그림의 처음 값이 이 예제입니다. 숫자를 넣고 그림으로 봐도 말이 되는지 확인하는 습관이 SLAM 디버깅의 절반입니다.

7. 코드로 확인하기

import numpy as np

def T_from(yaw_deg, tx, ty):
    th = np.deg2rad(yaw_deg)
    T = np.eye(3)                      # 2D 동차 변환 (3x3)
    T[:2, :2] = [[np.cos(th), -np.sin(th)],
                 [np.sin(th),  np.cos(th)]]
    T[:2, 2] = [tx, ty]
    return T

T_wb = T_from(90, 2, 1)
T_bc = T_from(0, 0.5, 0)
T_wc = T_wb @ T_bc                     # 첨자 b가 맞물림

p_c = np.array([1, 0, 1])              # 동차 좌표 (끝에 1)
print(T_wc @ p_c)                      # → [2.  2.5 1. ]

8. 핵심 정리

  1. pose = 회전 + 이동 = 강체 변환
  2. 회전 행렬의 열은 회전된 축의 방향이고, 역행렬은 전치다. 집합 이름은 SO(3)
  3. 회전은 순서가 중요하다. 교환법칙이 성립하지 않는다
  4. Twc는 c → w. 첨자를 오른쪽에서 왼쪽으로 읽고, 이어 붙일 때 안쪽 첨자가 맞물린다
  5. 동차 좌표를 쓰면 변환 연쇄가 행렬 곱 하나로 끝난다. 집합 이름은 SE(3)
  6. 역변환의 이동 부분은 -Rᵀt

다음 강 예고: 회전 행렬은 숫자가 9개인데 실제 자유도는 3개뿐이라 최적화 변수로 쓰기 불편합니다. 이 문제를 어떻게 푸는지가 2강(쿼터니언)과 3강(리 대수)의 주제입니다.
